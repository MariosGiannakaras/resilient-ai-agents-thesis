# A Formal Verification Framework for Runtime Assurance

## Βιβλιογραφική ταυτότητα

- **Συγγραφείς:** J. Tanner Slagel, Lauren M. White, Aaron Dutle, César A. Muñoz, Nicolas Crespo
- **Έτος:** 2023
- **Τύπος πηγής:** πρωτογενής εργασία formal methods και runtime assurance
- **Φορέας:** NASA Langley Research Center
- **NTRS:** 20230017350
- **Πρωτότυπο που ελέγχθηκε:** `πρωτότυπα/SRC-23A2C07D09.pdf`
- **Τεχνολογία:** Simplex Runtime Assurance, hybrid programs, PVS/Plaidypvs, differential dynamic logic

## Σκοπός και ερευνητικό ερώτημα

Η εργασία τυποποιεί και επαληθεύει μια Simplex Runtime Assurance (RTA) αρχιτεκτονική. Ένας προηγμένος αλλά μη έμπιστος controller—ο οποίος μπορεί να είναι AI/ML black box—λειτουργεί όσο ένα monitor επιβεβαιώνει τη συνθήκη ασφαλούς λειτουργίας. Όταν η συνθήκη αποτύχει, ο έλεγχος περνά σε trusted reversionary controller. Το ερευνητικό ερώτημα είναι υπό ποιες proof obligations μπορεί να αποδειχθεί ότι η συνολική αρχιτεκτονική διατηρεί μια safety invariant, ακόμη και όταν ο advanced controller δεν έχει επαληθευθεί εσωτερικά.

Για τη διπλωματική, η πηγή προσφέρει ένα διακριτό architecture baseline: **adaptive learning agent + runtime safety shield/fallback**. Αυτό δεν αυξάνει κατ’ ανάγκη τη μαθησιακή resilience του agent, αλλά μπορεί να περιορίσει unsafe outcomes ενώ ο agent υποβαθμίζεται ή προσαρμόζεται μετά από αλλαγή.

## Σύνοψη

Η Simplex RTA αρχιτεκτονική περιλαμβάνει:

- advanced controller (AC), πιθανώς υψηλής απόδοσης αλλά untrusted,
- reversionary controller (RC), απλούστερο και trusted,
- monitor/switch condition,
- system safety property,
- χρονικό όριο ανάμεσα σε monitor samples.

Η εργασία μοντελοποιεί advanced και reversionary systems ως hybrid programs και αποδεικνύει έναν γενικό RTA proof rule στο PVS/Plaidypvs. Η συνολική safety απόδειξη διασπάται σε υποχρεώσεις για την αρχική ασφαλή κατάσταση, τη συμπεριφορά του monitored advanced system και την ικανότητα του reversionary system να διατηρεί την safety property όταν γίνει η μετάβαση.

Το braking proof-of-concept δείχνει ότι δεν αρκεί ο monitor να ανιχνεύει μια επικείμενη παραβίαση· πρέπει να ενεργεί αρκετά νωρίς ώστε το fallback να έχει χρόνο να αποκαταστήσει ή να διατηρήσει την ασφάλεια. Η μέγιστη περίοδος sampling και η drift μεταξύ samples επηρεάζουν άμεσα το switch condition.

## Μεθοδολογία

- **Αρχιτεκτονική:** Simplex RTA με advanced controller, reversionary controller και runtime monitor.
- **Τυπική γλώσσα:** hybrid programs και differential dynamic logic embedded σε PVS μέσω Plaidypvs.
- **Safety objective:** invariant `S` που πρέπει να ισχύει σε κάθε run της συνολικής αρχιτεκτονικής.
- **Monitor:** switch condition `M` που ελέγχεται με μέγιστο sampling interval `τ`.
- **Switch condition:** περιλαμβάνει περιθώριο ώστε το reversionary controller να αναλάβει πριν παραβιαστεί το `S`.
- **Proof decomposition:** αρχική ασφάλεια, monitored advanced-system obligation και reversionary-controller obligation.
- **Proof of concept:** μονοδιάστατο automatic braking system με bounded positive acceleration και emergency braking.
- **Scope:** formal framework και μικρό hybrid-system example, όχι empirical RL benchmark.

## Κύρια ευρήματα

1. **Unverified AI/ML controller μπορεί να ενταχθεί σε verified outer architecture ως black box.** Η συνολική safety guarantee εξαρτάται από explicit assumptions, monitor και trusted fallback, όχι από εσωτερική επαλήθευση της policy. Τεκμηρίωση: PDF σελ. 1–2, Abstract και Section 1.1.

2. **Η RTA δεν είναι απλό alerting.** Το monitor συνδέεται σχεδιαστικά με action: όταν παραβιάζεται το switch condition, το reversionary controller αναλαμβάνει. Τεκμηρίωση: PDF σελ. 1–2, Section 1.1 και Figure 1.

3. **Η ασφάλεια απαιτεί πρόβλεψη πριν από την πραγματική παραβίαση.** Εάν ο monitor ενεργοποιηθεί μόνο όταν έχει ήδη αποτύχει η safety property, το fallback μπορεί να είναι πολύ αργό. Η switch condition πρέπει να περιλαμβάνει recoverability margin. Τεκμηρίωση: PDF σελ. 3–6, Sections 2–3.

4. **Το monitor sampling rate είναι μέρος της safety proof.** Η drift ανάμεσα σε samples πρέπει να ληφθεί υπόψη και υπάρχει μέγιστο επιτρεπτό `τ` για το braking example. Τεκμηρίωση: PDF σελ. 5–6, Equations (4)–(10).

5. **Η συνολική απόδειξη διασπάται σε ελέγξιμες υποχρεώσεις.** Αρχική condition, monitored AC και trusted RC πρέπει να συνδέονται μέσω switch property ώστε η invariant να διατηρείται. Τεκμηρίωση: PDF σελ. 4–5, RTA proof rule.

6. **Το framework αποδεικνύει safety, όχι task optimality ή learning quality.** Ένα fallback μπορεί να διατηρεί το `S` με χαμηλή utility ή αδράνεια. Αυτό πρέπει να μετράται ως intervention cost/availability loss. Τεκμηρίωση: scope και structure της εργασίας· συμπέρασμα από το δηλωμένο safety objective.

7. **Το switch-back δεν αποτελεί ολοκληρωμένο μέρος της κύριας formalization.** Η εργασία περιγράφει πιθανή επέκταση με πρόσθετη monitored condition, αλλά δεν παρέχει γενική ολοκληρωμένη recovery policy για επιστροφή στον AC. Τεκμηρίωση: PDF σελ. 4, Section 2.

## Υποθέσεις και ορισμοί

Για πιθανή GridWorld εφαρμογή:

- **Advanced controller:** ο υπό σύγκριση learning/adaptive agent.
- **Reversionary controller:** απλή verified ή exhaustively tested safe policy, π.χ. stop, retreat to safe cell ή shortest safe path σε γνωστό refuge.
- **Safety property `S`:** μη είσοδος σε hard hazard ή διατήρηση bounded risk budget.
- **Switch condition `M`:** condition αυστηρότερη από το `S`, ώστε να υπάρχει περιθώριο επέμβασης.
- **Intervention:** κάθε timestep/episode στο οποίο το fallback υπερισχύει της action του agent.
- **False intervention:** παρέμβαση όταν ο advanced agent θα παρέμενε ασφαλής.
- **Missed intervention:** μη παρέμβαση πριν από safety violation.

Σε διακριτό GridWorld χωρίς συνεχή drift, το sampling interval μπορεί να είναι ένα timestep. Παρόλα αυτά, η recoverability margin παραμένει σημαντική όταν μία action μπορεί να οδηγήσει μη αναστρέψιμα σε hazard.

## Περιορισμοί και απειλές εγκυρότητας

- Η πρωτογενής απόδειξη αφορά hybrid continuous/discrete braking example, όχι RL GridWorld.
- Formal guarantee ισχύει μόνο αν το model, bounds, monitor και trusted controller assumptions είναι ορθά.
- Η paper δεν αντιμετωπίζει πλήρως industrial deployment difficulties, concurrency ή πολύπλοκα switch-back protocols.
- Ένα runtime shield μπορεί να κρύψει την ανικανότητα του learning agent. Πρέπει να αναφέρονται raw agent performance και shielded system performance χωριστά.
- Η RTA μπορεί να μειώσει utility, exploration και learning coverage.
- Αν ο fallback δεν είναι πράγματι trusted ή η safe set είναι λανθασμένη, η εγγύηση καταρρέει.
- Σε άγνωστα changing environments, το monitor model μπορεί να γίνει obsolete.
- Δεν αποτελεί evidence ότι RTA είναι η καλύτερη resilience architecture· είναι safety containment mechanism.

## Σχέση με άλλες πηγές

- Συμπληρώνει το `SRC-3A5E2C9E2C`: παρέχει συγκεκριμένη outer-architecture λύση για safety constraints, διαφορετική από constrained policy optimization.
- Συνδέεται με `SRC-FE2C0A3E00`, όπου fail-safe intervention και safety properties μπορούν να αξιολογηθούν σε minimal environments.
- Περιορίζει `SRC-95C9DAEE68` και `SRC-0A594EACC0`: γρήγορο recovery δεν αρκεί εάν υπάρχει unsafe transient· RTA μπορεί να καλύψει το transient αλλά πρέπει να μετρά interventions.
- Συμπληρώνει `SRC-81A15E6905`: action perturbations μπορούν να ενεργοποιούν fallback, αλλά action robustness και runtime shielding είναι διαφορετικές λύσεις.
- Συνδέεται με `SRC-09DD20BA85`: lexicographic safety-first behavior μπορεί να υλοποιηθεί σε επίπεδο architecture μέσω override.

## Χρήση στη διπλωματική

- **Τι δεν πρέπει να ισχυριστούμε από αυτή την πηγή:** ότι GridWorld implementation είναι formally verified χωρίς ξεχωριστή proof· ότι RTA βελτιώνει learning/adaptation· ότι η απουσία violations αποδεικνύει καλό advanced agent.
- **Ρόλος:** υποστηρικτική αρχιτεκτονική πηγή και πιθανό safety-baseline design.

## Απαιτούμενα αποσπάσματα

1. Simplex AC/RC/monitor architecture.
2. Black-box AI/ML integration υπό formal outer guarantee.
3. RTA proof obligations.
4. Sampling delay και recoverability margin.
5. Όριο scope και μη ολοκληρωμένο switch-back.
6. Διάκριση safety guarantee από utility/resilience.
