# Evidence — Bayesian Online Changepoint Detection

## E1 — Posterior over time since the most recent change

- **Type:** faithful paraphrase
- **Location:** Abstract; Section 1
- **Claim:** Bayesian online changepoint detection can maintain a probability distribution over the current run length rather than returning only a binary alarm.
- **Status:** verified

### Faithful paraphrase

Adams and MacKay define the run length as the time elapsed since the most recent changepoint and perform causal online inference over its posterior distribution using only observations available up to the current time. The detector therefore represents multiple hypotheses about when the latest change occurred and attaches posterior probability to each hypothesis.

### Context and limits

The posterior is conditional on the chosen probabilistic observation model and changepoint prior. It is not model-free proof that the underlying MDP has changed.

### Thesis use

Use this source to separate detector confidence from downstream task performance and recovery.

### Citation

Adams and MacKay (2007), Abstract and Section 1.

## E2 — Hazard prior and predictive likelihood jointly drive the update

- **Type:** faithful paraphrase
- **Location:** Sections 2–2.3; Algorithm 1
- **Claim:** Each online update combines a prior probability of a run ending with the predictive probability of the new observation under each run-length hypothesis.
- **Status:** verified

### Faithful paraphrase

At each time step, posterior mass can either move from run length `r` to `r+1` or return to zero when a new changepoint is hypothesized. The hazard function specifies the prior probability of a changepoint, while the predictive distribution measures how compatible the new datum is with observations assigned to the current run. Recursive message passing and normalization yield the updated run-length posterior.

### Context and limits

For a geometric gap prior, the hazard is constant at `1/lambda`, so `lambda` encodes an assumed characteristic segment duration. Detector behavior therefore depends on prior and predictive-model choices.

### Thesis use

Treat hazard parameters and any alarm threshold as detector hyperparameters; evaluate false alarms, missed changes, and detection delay rather than calling the detector parameter-free.

### Citation

Adams and MacKay (2007), Sections 2–2.3 and Algorithm 1.

## E3 — Exact online inference has growing state unless hypotheses are pruned

- **Type:** faithful paraphrase
- **Location:** Section 2.4; Algorithm 1
- **Claim:** Maintaining all possible run-length hypotheses gives linear worst-case work and storage growth with sequence length; truncation can reduce average cost at the price of approximation.
- **Status:** verified

### Faithful paraphrase

Without truncation, a new possible run length is introduced at every observation, so the set of active hypotheses grows with time. The paper discusses discarding sufficiently small posterior-tail mass to reduce practical computation, while preserving the exact formulation as the reference algorithm.

### Context and limits

Any truncation rule introduces an additional approximation choice. Claims of low average complexity depend on the run-length distribution and pruning behavior, not on a universal constant-time guarantee.

### Thesis use

If BOCPD is implemented as a detector baseline, report its active-hypothesis count, memory use, and per-step detector cost.

### Citation

Adams and MacKay (2007), Section 2.4.

## E4 — Predictive uncertainty can increase immediately after a detected change

- **Type:** faithful paraphrase
- **Location:** Section 3; Figures 2–4
- **Claim:** When posterior mass shifts toward short run lengths after an abrupt change, predictions can become more uncertain because only a small amount of data is assigned to the new segment.
- **Status:** verified

### Faithful paraphrase

In the paper's empirical examples, abrupt changes are accompanied by posterior support for small run lengths. Immediately after such a reset, fewer observations support the parameters of the current segment, and the predictive distribution can widen until evidence accumulates under the new regime.

### Context and limits

This behavior follows from the fitted probabilistic models used in the examples; it should not be generalized automatically to arbitrary neural uncertainty estimators.

### Thesis use

Log detector uncertainty around known changepoints and keep uncertainty calibration separate from return-based recovery metrics.

### Citation

Adams and MacKay (2007), Section 3 and Figures 2–4.

## E5 — Detection is not adaptation

- **Type:** scope inference grounded in the paper
- **Location:** Sections 1–4
- **Claim:** BOCPD provides online changepoint inference and prediction, not an RL adaptation or recovery mechanism.
- **Status:** verified

### Faithful paraphrase

The method ends at posterior run-length inference and predictive filtering. It does not define an RL policy update, exploration response, knowledge reset, or task-recovery objective. In an adaptive-agent architecture, BOCPD can therefore serve as a detector component, while the rule that converts detector evidence into policy adaptation must be defined and evaluated separately.

### Context and limits

This is a boundary-of-scope conclusion. It must not be presented as if Adams and MacKay proposed a particular RL adaptation strategy.

### Thesis use

Maintain explicit detector-versus-adapter ablations and report detector metrics independently from recovery metrics.

### Citation

Adams and MacKay (2007), overall method scope, Sections 1–4.
