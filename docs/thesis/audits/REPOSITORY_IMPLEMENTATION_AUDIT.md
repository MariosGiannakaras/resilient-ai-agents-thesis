# Repository and implementation audit — T-716 pre-write

**Date:** 2026-09-05  
**Scope:** repository structure, historical implementation paths, writing artifacts, post-writing lifecycle, and organization debt relevant to producing the next full thesis.

## 1. Executive finding

The repository is not missing the scientific implementation or final evidence chain. The active scientific and application work is concentrated under `src/resilient_agents/`, `configs/`, `results/`, `research/`, `scripts/`, `tests/` and the current `docs/` authorities. What is confusing is that the repository also retains several early organizational scaffolds and superseded UI/application paths. Some are intentionally historical; some are empty-by-design output roots; some are stale placeholders that never became the primary authoring path.

The biggest writing-state problem was not lost science. It was composition drift: the T-714 full review manuscript reached about 20.9k whole-document words, then T-715 intentionally compressed the reader-facing narrative to about 12.7k while preserving figures and scientific values. The user rejected that compression. The next manuscript therefore restores a full-content baseline and integrates T-715 corrections rather than continuing the compressed branch.

## 2. Repository paths: active, contractual, historical, or stale

### Active scientific/application paths

- `src/resilient_agents/` — accepted implementation core: GridWorld, methods/adapters, Study backend, evidence/statistics and PySide6 application/read-model layers.
- `configs/` — protocol and experiment configuration authority, including the final protocol-v2.1 contract.
- `results/` — accepted experiment/evidence/analysis/thesis-asset outputs and immutable manifests.
- `research/bibliography/` — synchronized ThesisBibliography consumer corpus and strict `citation-ready/` layer.
- `scripts/` — experiment, validation, bibliography, thesis-composition and audit tooling.
- `tests/` — active regression/contract tests.
- `docs/` — decisions, protocol/research interpretation, current-state ledgers, official-guidance snapshots and thesis-writing authorities.
- `thesis/archive/` — persistent retained DOCX milestones and QA reports.
- `thesis/drafts/` — user-restored historical Word drafts (stage3/6/8/9).

### Deliberate generated-output contracts

- `artifacts/` is a recognized generated-output prefix in the implementation (`run_bundle`, publication and system-inventory code). Its mostly empty `exports/`, `figures/` and `tables/` substructure reflects output staging rather than missing source implementation. The accepted final scientific assets now live under versioned `results/thesis-assets/`, so the old generic subfolders are rarely populated.
- `data/` contains historical/raw staging roots. The final study did not depend on a conventional static dataset because evidence is generated by controlled RL execution and stored as run bundles/results.

### Writing scaffolds that did not become the primary authoring path

- `thesis/chapters/` remained largely a structural placeholder. The actual T-710/T-711 manuscript source became `docs/thesis/draft/`. The string `thesis/chapters/` is also retained in bibliography-usage validation as a formal-document path convention, so the directory name is not wholly accidental even though it was not populated as the final source tree.
- `thesis/appendices/` similarly remained a placeholder while the real appendix source was `docs/thesis/draft/APPENDIX_DRAFT.md` and later composed DOCX content.
- `thesis/final/` is intentionally sparse: by policy it is reserved for genuinely accepted final/submission candidates, not review milestones.

## 4. Citation/bibliography diagnosis

T-714 contains 17 formal IEEE references and all 17 are actually cited. It has 78 valid bibliography-number mentions. This is structurally correct but bibliographically narrow for the desired final scope. Most external literature use is concentrated in Chapters 1, 2 and 6, with essentially no formal literature citation density in Chapters 3, 4, 5 and 7.

The synchronized bibliography contains 599 canonical source records, 599 analyses, 147 evidence records and 123 citation-ready records. The writing audit surfaced 57 distinct additional citation-ready candidates with direct relevance. Therefore the low reference count is a composition-selection problem, not a lack of researched material.

## 6. Organization decision for T-716

Do not perform a broad cleanup before the new thesis build. Removing scaffolds now risks deleting path contracts or useful historical provenance for little benefit. T-716 instead follows these rules:

- source of scientific truth remains the accepted protocol/evidence/analysis assets;
- T-714 is the full composition baseline;
- stage9 is an explanatory-content donor only after claim-by-claim reconciliation;
- T-715 audit corrections are mandatory overlays;
- new bibliography content uses only `citation-ready/` sources for formal citations;
- seminar/YouTube/transcript material may inform synthesis but is not formal evidence unless its primary publication is independently promoted/verified;
- every new DOCX/QA milestone is committed under `thesis/archive/` before handoff;
- `thesis/final/` remains untouched until final acceptance gates are met.

A later bounded repository-hygiene pass can remove or rewrite obsolete placeholder READMEs once T-716 has established the final writing/build paths. Scientific evidence, decision history, final protocol authority and historical delivered documents are never cleanup targets.
