# Bibliography Integration Contract

**Status:** active project architecture  
**Canonical bibliography repository:** `MariosGiannakaras/ThesisBibliography`

## Boundary

`ThesisBibliography` owns the complete bibliography lifecycle: discovery, metadata, originals, conversion, scientific analysis, evidence extraction, selection, and controlled export.

`resilient-ai-agents-thesis` owns the thesis, research design, implementation, experiments, results, writing, and presentation. It does not own primary-source ingestion or bibliography curation.

The repositories keep separate histories. There is no submodule and no write path from the thesis repository into `ThesisBibliography`.

## Imported surface

The only bibliography content consumed by this repository is the generated directory:

```text
research/bibliography/
├── README.md
├── SOURCE_COMMIT
├── IMPORT_INTEGRITY.json
├── manifest.csv
├── catalog/
│   └── sources.csv
├── analyses/
└── evidence/
```

`SOURCE_COMMIT` must be the exact checked-out `ThesisBibliography` commit used to run its exporter. `IMPORT_INTEGRITY.json` is generated by this repository and binds every imported file to its SHA-256 digest.

The imported surface must never contain PDFs, original/source archives, Git LFS pointers, conversion workspaces, unverified analyses, or unverified evidence.

## Source language

Canonical source-derived scientific text remains in the original source language. The import process never translates evidence. Translation for the final Greek thesis is a writing-stage operation and does not replace the original-language evidence record.

## Source identifiers

Canonical source references use the `SRC-XXXXXXXXXX` identifiers exported by `ThesisBibliography`.

Every canonical `SRC-*` identifier used in thesis repository text must exist in the imported `manifest.csv`. Claims must be grounded in the corresponding verified evidence and interpreted with the associated analysis/limitations.

## Synchronization

Synchronization is intentionally pull-based. It can start in either of two controlled ways:

- **Pinned/manual:** dispatch `.github/workflows/sync-bibliography.yml` with a specific bibliography branch, tag, or commit.
- **Latest-main automation:** change `.bibliography-sync-trigger` on `main`; this synchronizes the current `ThesisBibliography/main` head.

After either trigger:

1. The workflow checks out `ThesisBibliography` using the read-only `BIBLIOGRAPHY_SYNC_TOKEN` secret.
2. The canonical exporter runs in that exact checkout.
3. `scripts/bibliography_import.py` validates the exported package and transactionally replaces only `research/bibliography/`.
4. `scripts/validate_bibliography_usage.py` verifies package integrity and source-ID references.
5. The workflow opens a Pull Request to this repository.
6. Normal CI/review applies before merge.

A bibliography synchronization never merges directly to `main`. The trigger file contains no bibliography data and exists only to request a latest-main synchronization when manual workflow dispatch is not available to the automation client.

## Freshness gates

Fresh literature searches remain required at the established thesis gates, but they are executed in `ThesisBibliography`. This repository receives their verified results only through a new controlled export/sync.

Before protocol freeze, major writing gates, and final submission, record the imported `SOURCE_COMMIT` used by the thesis state under review.

## Legacy main-repository bibliography files

Older files under `bibliography/` and the former download script are historical compatibility markers only. They must not be treated as an active acquisition workflow or updated with new primary-source material.
